There is no preprocessing stage in this codebase — the pipeline is decode → VAD → ASR → glossary — so there is no denoise toggle to offer. Denoising measured +26% mean WER on this stack, worse in 9 of 13 conditions, one case above WER 1.0 from hallucination. This note exists so nobody adds it back.
The glossary is a startup file (/etc/stt-stack/glossary.txt), not a request field. The per-request vocabulary fields prompt and keywords[] are both 400 on Parakeet. An irrelevant glossary cost +12% WER on Parakeet and +28% on Whisper, which is a finding no slider can express.

The prefix map is published: a→en-us, b→en-gb, e→es, f→fr-fr, h→hi, i→it, j→ja, p→pt-br, z→cmn. /speak defaults to en-us, so a UI that omitted this would mispronounce every Portuguese request while looking right.
The field is format on /speak (default wav) and response_format on /v1 (default mp3). Different names, different defaults — they do not share a request builder.
/speak is extra="forbid": an unknown field is a 422. /v1 is extra="allow" and reports what it ignored in X-Ignored-Parameters, which this page surfaces.

Submission is always POST /jobs: it answers 202 every time, with chunks and the server's own estimated_seconds, and it survives a closed laptop. The /v1 SSE path is not offered as a default because closing that stream cancels the job, and because the same request can answer 200-audio, 200-event-stream or 202 with JSON depending on arithmetic — a naive client writes the third into a .wav.
